# Turbo-страницы: RSS-фид (Этап 1)

**Контекст:** 25.07.2026. Продолжение SEO-работы (см. `docs/superpowers/plans/2026-07-24-seo-backlink-building.md`). Диагностика через Яндекс.Вебмастер API показала, что коммерческие запросы новых клиентов («ремонт телефонов вологда» и т.п.) ранжируются низко (позиция 18-22). Турбо-страницы — способ ускорить мобильную загрузку и получить дополнительную видимость в мобильной выдаче Яндекса без переписывания самого сайта.

**Цель Этапа 1:** сгенерировать корректный RSS-фид для Яндекс.Турбо по всем страницам услуг и новостям, с формой-заявкой внутри, подключить в Яндекс.Вебмастере.

**Явно отложено на Этап 2 (отдельная задача):** автоматический перенос заявок из формы Турбо (email) в систему бронирования (`/api/bookings`). Форма Турбо технически умеет присылать заявки только на email — прямого вебхука в схеме Турбо нет (проверено на реальном коде трёх независимых open-source генераторов Turbo-фидов). Автоматизация потребует отдельного email-парсера и решения по IMAP-доступу к почтовому ящику — сознательно не делается сейчас, чтобы не блокировать более простую и ценную первую часть.

## Архитектура

Новый Route Handler: `src/app/api/turbo-feed/route.js`.

- `export const dynamic = 'force-dynamic';`
- In-memory кэш с TTL 5 минут — тот же паттерн, что уже используется в `src/app/api/services-yml/route.js` (модуль-level переменная `cache = { data, timestamp, ttl }`, без внешнего кэш-слоя).
- `GET` подключается через `dbConnect()`, параллельно тянет:
  - `Service.find({ isCategory: false }).lean()` — все 123 услуги (не категории).
  - `News.find({ isPublished: true }).lean()` — все опубликованные новости (сейчас 4).
- Собирает RSS 2.0 XML-строку вручную (как и `services-yml`/`yml` роуты уже делают — без внешней XML-библиотеки, конкатенация строк с экранированием).
- Возвращает `Content-Type: application/xml; charset=utf-8`, `Cache-Control: public, max-age=300`.

## RSS-структура

Корневой тег:
```xml
<rss xmlns:yandex="http://news.yandex.ru" xmlns:media="http://search.yahoo.com/mrss/" xmlns:turbo="http://turbo.yandex.ru" version="2.0">
```

`channel`:
- `title` = `BUSINESS.shortName`
- `link` = `BASE_URL`
- `description` = `SEO_DEFAULTS.description`
- `language` = `ru`

`item` для услуги (`turbo="true"` атрибут на `<item>`):
- `title` = `service.metaTitle || `${service.name} в Вологде``
- `link` = `${BASE_URL}/services/${service.slug}`
- `pubDate` = `service.updatedAt` (RFC-822 формат)
- `guid` = значение `link` (без `isPermaLink`, т.к. это просто уникальный идентификатор)
- `turbo:content` (обёрнуто в `<![CDATA[...]]>`):
  ```html
  <header><h1>{name}</h1></header>
  <p>{description}</p>
  {price ? `<p><strong>Стоимость:</strong> {price}</p>` : ''}
  <form data-type="callback" data-send-to="s89062960353@yandex.ru"></form>
  ```
  Форма — самозакрывающийся элемент без дочерних полей: Турбо сам рендерит все поля ввода и кнопку на основе `data-type="callback"` (подтверждено исходным кодом open-source генераторов, использующих этот же виджет).

`item` для новости:
- `title` = `news.metaTitle || news.title`
- `link` = `${BASE_URL}/news/${news.slug}`
- `pubDate` = `news.publishedAt`
- `guid` = `link`
- `turbo:content`:
  - Блоки `contentBlocks` конвертируются в HTML по типу:
    - `text` → `<p>{content}</p>`
    - `heading` → `<h2>{content}</h2>`
    - `list` → `<ul>{каждая строка content как <li>}</ul>`
    - `image` → `<figure><img src="{media}" alt="{alt}" /></figure>`
    - `video`/`youtube` → на Этапе 1 пропускаются (не конвертируются) — сложные видео-виджеты Турбо не входят в объём этой задачи; если видео-блок единственный контент новости, используется `excerpt` как fallback
  - Если после сборки блоков контент пустой (например, только видео) — используется `excerpt`
  - Форма-заявка в новостях не добавляется (не относится к бронированию)
- Если есть `featuredImage` — картинка вставляется прямо в начало `turbo:content`: `<header><figure><img src="{featuredImage}" /></figure><h1>{title}</h1></header>` (реальный формат Турбо для обложки — картинка внутри `<header>`, а не отдельный RSS-тег `enclosure`; так делают все проверенные open-source генераторы фидов)

## Обработка ошибок

Тот же принцип, что в `services-yml/route.js`:
- Ошибка при обработке **одной** услуги/новости — `console.error`, элемент пропускается, генерация продолжается для остальных.
- Критическая ошибка (нет соединения с БД) — возвращается fallback-XML с пустым `<channel>` (валидный, но без items), статус 500, `Cache-Control: no-cache`.
- Экранирование текста — переиспользуется существующая функция `escapeXml` (или её аналог) из `services-yml/route.js`; отдельно проверяется вхождение литеральной последовательности `]]>` внутри пользовательского текста (ломает `CDATA`) — заменяется на `]]&gt;` при обнаружении.

## Тестирование

- `npm run build` проходит без ошибок.
- `curl /api/turbo-feed` возвращает валидный XML: проверка через `xmllint --noout` или `python3 -c "import xml.dom.minidom; xml.dom.minidom.parse(...)"`.
- Подсчёт items в ответе — ожидается 123 (услуги) + 4 (новости) = 127, без дублей `guid`.
- Выборочная проверка: `link` каждого item отвечает 200 на реальном домене.
- Финальная проверка — через инструмент «Турбо-страницы» в Яндекс.Вебмастере после добавления URL фида (`https://servicebox35.ru/api/turbo-feed`): смотрим на ошибки/предупреждения валидации самого Яндекса.

## Явные ограничения объёма (Этап 1)

- Не включаются страницы каталога запчастей (`/product/[slug]`, `/parts`) — не обсуждалось в рамках этой задачи, отдельное решение при необходимости.
- Не подключается автоматический перенос заявок из email в бронирование (Этап 2).
- Видео-блоки новостей не конвертируются в турбо-разметку (см. выше).
